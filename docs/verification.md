# 검증 기록

## 1차 리팩토링 품질·안정성 검토 · 2026-11-07

- [상세 보고서와 실기기 체크리스트](quality-review.md)에 확인된 문제, 수정 이유, 유지한 책임 경계와 남은 위험을 기록했다. 추가 파일 분리·스키마·API·암호화 포맷·동기화 프로토콜 변경은 없다.
- 지연된 복구 키 생성 결과를 취소하고, 백업·첨부 읽기 완료 후 공유 직전에 접근 권한을 재검사한다. 앱 시작 시 중단된 JSON 공유 캐시도 정리한다. 백업 가져오기에서는 복원 blob descriptor를 한 번 인덱싱하도록 했다.
- 변경 전 **25파일 / 139개**, 변경 후 **28파일 / 152개 테스트 통과**. 실제 SQLite WAL 쓰기 프로세스 강제 종료, 업로드 응답 유실 후 DB 재개방·같은 암호문 재전송, 다중 첨부 복원, 인증 취소·실패, 공유 직전 접근 만료와 캐시 정리 경계를 보강했다. 네이티브 관련 테스트는 모킹이며 실기기 검증을 대신하지 않는다.
- `pnpm check-types`, `pnpm lint`, `pnpm format:check`, `pnpm build`, Expo `install --check`, Android/iOS JS export가 통과했다. 기존 서식 경고 2건은 AGENTS.md의 빈 줄과 mobile tsconfig.json의 배열 배치였으며 의미를 바꾸지 않고 정리했다. 아래 과거 기록의 서식 경고는 당시 결과다.
- 빌드된 서버에 `node scripts/smoke-production.mjs`를 실행해 임시 DB·파일 저장소의 실제 HTTP, 첨부 전송, 백업 검증/복원, 재시작 영속성과 세대 갱신을 확인했다. 전체 테스트의 자식 프로세스 실행은 샌드박스 OS 사용자 정보 조회 제한으로 실패하여 승인된 일반 실행 환경에서 다시 검증했다.
- Docker 명령이 없어 컨테이너 빌드·기동·볼륨은 미검증이다. 이번에는 네이티브 빌드·iOS/Android 실기기·실제 S3 검증을 수행하지 않았다. 실제 사용자 DB·NAS에 접근하거나 배포하지 않았다.

- 서버 checkpoint 검증과 라우트 등록을 분리했으며 기존 DB 연결·트랜잭션·Fastify 인증 scope를 유지했다. 키 등록/평문 이력 검사·충돌·receipt·revision 처리는 NotesRepository에 남겼다. DB 스키마·저장/암호문 포맷·API·프로토콜 변경은 없다. 원본 소스와 AST/SQL/화면 선언을 비교했다.

- 네이티브 의존성/설정 변경이 없어 이번에는 네이티브 재빌드를 하지 않았다. iOS 빌드는 Windows 환경에서 실행하지 않았다. Docker 명령이 없어 컨테이너/볼륨 검증은 미실행이다. 실제 사용자 DB·NAS·S3를 수정하거나 배포하지 않았고 iOS/Android 실기기 검증도 실행하지 않았다. 인증·파일 선택·미리보기·공유 테스트는 네이티브 API 모킹이며 실제 앱 전환/OS 인증·SQLCipher·키보드·테마 검증을 대체하지 않는다.

## 사진·파일 첨부와 서버 디스크/S3 · 2026-11-07

- 편집기 클립 메뉴에 사진 원본 크기·2560px·1280px 및 일반 파일 선택을 추가했다. 사진은 본문에 이미지로, 일반 파일은 열기·공유 카드로 표시한다. 작은 사진을 확대하지 않고 비율을 유지하며 PNG는 투명도를 유지한다. 표시용 미리보기는 원본과 별도로 최대 1024px로 만들고 본문 viewport 근처부터 읽는다. 네이티브 이미지 처리는 직렬화하고 완료 promise에 평문 이미지 URI를 보관하지 않는다. 앱 비활성화·카테고리 권한 변경 시 늦은 결과를 버린다.
- 파일당 20MiB·메모당 64개, 서버 계정별 기본 1GiB 한도를 적용했다. 로컬 첨부·메모·outbox를 하나의 SQLCipher 트랜잭션으로 저장하고 256KiB 조각별 E2EE·고유 nonce·계정/파일/순서/개수 AAD·전체 평문 해시를 검증한다. 암호문 재전송 캐시로 응답 유실을 재시도하고 파일 완료 후에만 메모를 전송한다. 파일 이름·종류·크기·해상도는 암호화된 메모 안에 둔다.
- 서버 디스크와 공식 AWS SDK 기반 S3/S3 호환 저장소를 추가했다. 서버는 사용자 소유 범위를 검사하고 불변 암호문 키로 저장한다. 조건부 쓰기와 기존 바이트 일치 검증으로 덮어쓰기를 막으며, 기존 저장소와 설정이 달라지면 시작을 차단한다. S3 자격 증명은 서버 credential chain으로 공급하며 앱이나 이미지에 넣지 않는다. S3 어댑터는 SDK 모킹 테스트로 확인했고 실제 버킷에는 접속하지 않았다.
- 서버 DB v4는 v1/v2/v3 파일의 사전 `.before-v4-UUID.db` 백업 후 첨부 manifest 테이블을 추가한다. 로컬 v3는 첨부·조각·재전송 테이블을 추가한다. 기존 메모·outbox·UUID·ciphertext·receipt·서버 식별자/세대·checkpoint를 보존하는 마이그레이션을 검증했다. 동기화 v4를 사용하고 v1/v2/v3 앱은 426으로 차단한다. 기존 첨부 없는 E2EE envelope와 재전송 암호문은 재작성하지 않는다.
- JSON v2에 첨부 바이트를 포함하고 v1도 계속 지원한다. 복구 사본은 본문의 논리적 첨부 링크를 유지하면서 새 저장 객체 UUID를 만들어, 중간에 끊긴 업로드 예약과 충돌하지 않도록 했다. 파일 누락·해시 오류·트랜잭션 실패는 전체 거부한다. 서버 백업은 DB 스냅샷과 `.attachments` sidecar·완료 marker를 함께 만들며 `backup:verify`로 DB 무결성과 모든 완료 파일의 해시를 검증한다. 자동 GC·저장소 간 자동 이전·키 교체·사용자용 수정 이력은 포함하지 않는다.
- **19개 파일, 129개 테스트 통과.** 파일/메모/outbox 원자적 롤백·청크 변조/순서/계정 교체 거부·미확인 전송 재시도·다른 기기 다운로드·오프라인 충돌·카테고리 접근·부분 업로드 후 JSON 복구·원문 보존·계정 분리·쿼터·이전 프로토콜 차단·DB+파일 백업 누락 차단·모킹 S3 조건부 쓰기를 검증했다. 사진 선택·축소의 native API 인수·디코딩 크기 제한·취소·소유 캐시 정리는 모킹 검증이다.
- `pnpm check-types`, `pnpm lint`, `pnpm build`, Expo `install --check`, Android/iOS JS export가 통과했다. `pnpm format:check`는 기존 `AGENTS.md`, `apps/mobile/tsconfig.json` 경고 2건만 남는다. 프로덕션 의존성만 포함한 별도 로컬 폴더에서 빌드 산출물로 smoke를 실행해 실제 HTTP 첨부 업로드·다운로드, DB+blob 백업/검증·별도 경로 복원·세대 갱신 후 기존 checkpoint 차단과 파일 복호화를 확인했다. 네트워크 제한으로 중단된 초기 패키징은 승인된 다운로드로 새 검증 폴더에 다시 수행했다.
- `pnpm apk:debug --arm64`로 **Android Development Build 성공**. 결과: `dist/apk/YeongduMemo-0.1.0-debug-arm64.apk`(Metro 필요). 새 `expo-image-picker`·`expo-image-manipulator` 네이티브 모듈을 포함한다. iOS 네이티브 빌드는 실행하지 않았다. 양 플랫폼 실기기의 사진/파일 제공자·EXIF 회전·PNG 투명도·키보드/긴 메모·이미지 표시·공유·생체 인증·OS 암호 폴백·SQLCipher 실효성·최근 앱 화면·테마는 이번에 확인하지 않았다.
- Docker 명령을 찾을 수 없어 컨테이너/볼륨·amd64/arm64 Docker 검증은 미실행이다. 실제 AWS/MinIO 인증·정책·TLS·업로드 장애도 미검증이며 실제 S3·NAS·사용자 DB에는 접근·배포·변경하지 않았다. 테스트는 메모리/임시 DB와 테스트 전용 임시 파일, S3 모킹만 사용했다. [운영 문서](attachments.md)에 한도·보존·설정·복원 절차와 남은 검증을 기록했다.

## NAS 배포 전 백업·복구 안전장치 · 2026-11-07

- 실제 사용자 DB와 NAS에는 접근·배포·변경하지 않았다. SQLite/Fastify 테스트는 메모리 DB 또는 테스트 전용 임시 디렉터리, 프로덕션 smoke도 생성한 임시 DB·계정·키만 사용했다.
- 서버 v3 마이그레이션 전에 v1/v2 파일의 온라인 백업을 생성한다. 기존 메모·세션·receipt·revision을 보존하면서 서버 식별자·세대·change별 checkpoint 토큰을 추가했다. 읽기 전용 백업 CLI가 스키마를 변경하지 않고 기존 대상 파일을 덮어쓰지 않는 것을 검증했다.
- 정상 재시작·동일 DB 이동, 오래된 백업으로 복원, 번호가 다시 커진 다른 이력 분기, 검사와 push 사이의 DB 식별자/세대 변경, 구버전 checkpoint 없는 로컬 DB와 v2 클라이언트 차단을 검증했다. 복원 감지 시 업로드·삭제·ack 전에 중단하고 오프라인 원문·operation UUID·cursor·checkpoint를 유지하며 중단 사유를 로컬 metadata에 저장한다. 정상 서버가 돌아와도 자동 해제하지 않는다.
- JSON 형식 전체 검증·파일 내 중복 ID 거부·오류에서 민감한 원문 비노출·기존 메모 새 ID 사본 처리·Markdown 원문/시각·휴지통·충돌 참조·영구 삭제 표식 제외·카테고리 이름 분리와 보호 계승·인증 취소·오래된 확인 무효화·일부 쓰기 실패 시 전체 롤백·동기화 중단 유지·일반 암호문 동기화를 검증했다. OS 파일 선택 후 정상 앱 잠금 해제 전 평문을 읽지 않는 경계와 구서버 404 업그레이드 안내도 모킹 기반으로 확인했다.
- 복구 키 보관 확인·재입력 일치 검증, 서버/계정/키 식별자별 SecureStore 저장, 기기 인증 후 오프라인 재조회, 이전 설치 인덱스 보완, 인증 취소·잠금·키 소실 시 자동 생성 금지를 검증했다. Expo Crypto·SecureStore·기기 인증·파일 선택기는 모킹했으며 네이티브 암호화나 OS 인증 실효성을 검증했다고 주장하지 않는다.
- **17개 파일, 115개 테스트 통과.** `pnpm check-types`, `pnpm lint`, `pnpm build`, Expo `install --check`, Android/iOS `expo export --platform all --output-dir dist --no-bytecode`가 통과했다. 새 네이티브 의존성은 추가하지 않았다. 전체 `pnpm format:check`는 기존 `AGENTS.md`, `apps/mobile/tsconfig.json` 경고 2건으로 실패하며 이번 변경 파일의 서식은 정리했다.
- 빌드 산출물을 사용하는 `node scripts/smoke-production.mjs`가 통과했다. CLI 계정 생성 → v3 HTTP 동기화 → 온라인 백업 → 재시작 보존 → 별도 임시 경로에 옛 백업 복사 → CLI의 사전 백업과 세대 갱신 → HTTP에서 `generation_changed` 차단·백업 원문 복호화를 검증했다. 원래 최신 테스트 DB도 복구 검증 동안 보존했다.
- `docker version`은 명령을 찾지 못했다. Docker Engine·컨테이너·볼륨·amd64/arm64 검증은 실행하지 않았다. APK/iOS 네이티브 빌드·iOS/Android 실기기 파일 제공자 선택·생체 인증·OS 암호 폴백·최근 앱 화면·SQLCipher·키보드·긴 메모·테마 검증도 이번에 실행하지 않았다. NAS 복원 연습·배포·레지스트리 게시도 수행하지 않았다.
- 키 교체는 기존 단일 keyId·AAD·오프라인 outbox·receipt·변경 로그·백업의 안전한 전환 조건이 없어 구현하지 않았다. [운영·복구 절차](operations-recovery.md)에 필요한 설계 결정을 기록했다. 첨부파일·사용자용 수정 이력도 구현하지 않고 [도입 조사](storage-roadmap.md)에 저장·E2EE·동기화·삭제·보존·백업·마이그레이션과 결정 시점을 정리했다.

## 카테고리별 잠금·숨김과 보호 설정 동기화 · 2026-11-07

- 사용자가 다른 기기에도 동기화하는 방식을 선택했습니다. 각 메모의 암호화된 내용에 `categoryProtection`(locked/hidden)을 추가하고 기존 메모는 false/false로 읽습니다. 해당 카테고리의 모든 메모·휴지통 항목에 보호 설정과 outbox를 한 트랜잭션으로 기록하고 기존 서버 revision·operation UUID 재시도 체계를 사용합니다. 로컬 DB v2와 E2EE 프로토콜 v1은 그대로이며 파괴적인 마이그레이션이나 서버 평문 필드는 추가하지 않았습니다.

## Android 시작 오류 수정

연결된 Android 기기에서 `URI is not absolute` 오류 화면을 재현했습니다. SQLite의 네이티브 기본 DB 디렉터리를 FileSystem의 `File`에 직접 전달했던 것이 원인이었습니다. DB 위치는 유지하면서 FileSystem에 전달하는 값만 `file://` URI로 변환했습니다.

경로 변환과 실제 `openVault` 호출 경계에 대한 회귀 테스트를 추가했으며 자동화 테스트 27개, 타입·린트 검사가 통과했습니다. 일반/arm64 release APK를 다시 생성했고, 일반 APK를 `adb install -r`로 업데이트한 기기에서 메모 목록 화면 표시와 JS/AndroidRuntime 오류 로그 부재를 확인했습니다. 앱 데이터 삭제·앱 제거는 수행하지 않았습니다. 전체 CRUD·생체 인증·iOS 검증을 대신하는 결과는 아닙니다.

## 테스트 범위

아이콘·실시간 Markdown 편집 변경에서는 자동화 테스트 32개가 통과했습니다. 추가한 5개 테스트는 표준 강조·제목 범위, 코드 영역 내 문법 제외, 이스케이프, 링크/목록/인용 및 긴 메모 제한을 검증합니다. Android·iOS Metro export, Expo 버전 검사와 peer 검사도 통과했습니다. 실제 기기가 연결되지 않아 이번 변경의 OS별 시각적 세부 표현·한글 IME·iOS 네이티브 실행은 별도 확인이 필요합니다.

읽기 전용 Android 에뮬레이터에서 release APK로 설정 SVG 아이콘과 화면 이동, 네이티브 실시간 편집 진입, 원문/미리보기 전환, 저장 후 재열기 및 원문 보존을 확인했습니다. 화면 캡처 보호 설정은 유지했습니다.

최종 APK에서도 동일 UI 검증이 통과했으며, Markdown 본문의 자동 대문자화를 꺼 소문자 코드·문법 입력을 유지합니다. 전체 아키텍처 release 빌드와 arm64 Development Build가 통과했습니다. 결과물은 `dist/apk/YeongduMemo-0.1.0-release.apk`와 `dist/apk/YeongduMemo-0.1.0-debug-arm64.apk`입니다. Development APK는 Metro가 필요합니다. 이번 작업에서 실제 휴대전화에는 설치하지 않았습니다.

- 로컬 DB CRUD·검색·즐겨찾기·보관·휴지통·복원·영구 삭제·재오픈·outbox 보존.
- Markdown 원문의 줄바꿈·공백·서식 보존, 렌더링 파서의 표·체크리스트·H1–H6 및 raw HTML/script URL 차단.
- 자동 저장 debounce·flush·직렬 쓰기·실패 복구와 오래된 실패/새 입력 간 경합. 전용 쓰기 연결의 커밋 이전 읽기 격리와 오류 발생 시 트랜잭션 롤백.
- 시스템 테마·수동 테마 선택과 두 팔레트 토큰 대응. 네이티브 색상 렌더링은 실기기 미검증.
- 잠금 정책과 잠금 후 repository 읽기·쓰기·내보내기 차단. OS 생체 인증 호출 자체는 미검증.
- 서버 요청 검증·회원가입 비활성·사용자 분리·Argon2id·인증 실패·요청 횟수 제한·토큰 만료·회전·재사용 시 폐기·로그아웃.
- revision/cursor·증분 페이지·멱등 재전송·operation ID 내용 불일치 거부.
- 오프라인 작성·연결 복구·서버 수락 후 응답 유실·두 기기 수정 충돌·전송 중 추가 입력 및 충돌 사본으로 후속 입력 이동.
- 삭제·복원·영구 삭제 tombstone과 원격 변경 수신 시 미전송 편집 보존.
- 서버 파일 DB 재오픈 및 프로덕션 프로세스 재시작 후 영속성. Docker 재시작 검증을 대신한다고 주장하지 않음.

## 재현 명령

```sh
pnpm install --frozen-lockfile
pnpm verify
pnpm format:check
pnpm build
pnpm --filter @yeongdu/mobile exec expo install --check
pnpm peers check
pnpm --filter @yeongdu/mobile exec expo export --platform all --output-dir dist --no-bytecode
pnpm --filter @yeongdu/mobile exec expo prebuild --platform android --no-install
# apps/mobile/android에서:
./gradlew :app:assembleDebug -PreactNativeArchitectures=arm64-v8a
# 루트에서:
pnpm --filter @yeongdu/server deploy --prod .artifacts/production-new
node scripts/smoke-production.mjs .artifacts/production-new
```

Android 개발 APK: `apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk`. JS는 `pnpm mobile`의 Metro 서버에서 로드하는 개발용 빌드이며 배포용 서명 APK가 아닙니다.

추가한 `pnpm apk --arm64` 명령으로 release APK 빌드와 `dist/apk/YeongduMemo-0.1.0-release-arm64.apk` 내보내기를 검증했습니다. APK 내부의 JavaScript 번들·arm64 SQLite 네이티브 라이브러리 포함 여부와 `apksigner verify`의 v2 서명 검증이 통과했습니다. 현재 서명은 생성된 네이티브 프로젝트의 개발용 keystore 설정을 따릅니다. 전체 아키텍처 빌드와 실기기 실행은 이번 검증에 포함하지 않았습니다.

CI에는 `scripts/smoke-docker.mjs`로 컨테이너에 계정/메모를 만들고 재시작 후 실제 메모·세션 보존을 확인하는 단계가 포함되어 있습니다. 이 환경에서는 실행하지 않았습니다.

테스트용 임시 DB와 무작위 계정은 테스트 종료 시 정리합니다. `.artifacts/`의 로그·독립 배포물과 앱의 `dist/`, 네이티브 생성물은 Git 대상이 아닙니다.
