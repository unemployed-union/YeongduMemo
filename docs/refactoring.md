# 동작 보존 리팩토링 · 2026-11-07

현재 코드와 AGENTS.md를 읽고 호출 관계·트랜잭션·인증 세션을 기준으로 분리했다. 파일 길이를 분리 기준으로 삼지 않았다. DB 스키마·SQL 마이그레이션·저장 형식·Markdown 원문·E2EE 포맷·HTTP API·동기화 버전은 변경하지 않았다. 실제 사용자 DB·NAS·S3에는 접근하거나 배포하지 않았다.

`LocalBackups`의 context는 새 범용 저장 추상화가 아니다. DB 읽기, 동일한 `CategoryAccess`, 기존 파일 저장 모듈과 LocalStore의 write/queue/transaction 함수를 명시적으로 받는다. 가져온 첨부·메모·outbox 전체는 여전히 LocalStore가 시작한 **하나의 트랜잭션**에 들어간다. 권한이 취소되면 같은 인증 세대와 확인 정보를 폐기한다. 일반 저장·원격 적용·백업이 서로 다른 큐를 사용하지 않는다.

## 검토했지만 유지한 부분

- 메모 저장·outbox 갱신·첨부 추가의 커밋, `acknowledge`의 전송 중 수정/충돌 사본 처리, `applyRemote`의 메모·cursor·checkpoint 적용은 분리하지 않았다. 쪼개면 서로 다른 revision이나 추가 입력을 커밋할 위험이 커진다.
- 카테고리 메타데이터 조회와 보호 변경은 LocalStore에 남겼다. 읽기 접근, 새/이전 카테고리 확인, 전체 멤버의 outbox 및 원격 변경 시 세션 폐기를 함께 판단하기 때문이다. 메모리 인증 상태는 기존 `CategoryAccess` 하나만 유지한다.
- 편집 화면의 커서·입력 ref·서식 삽입·뒤로 가기/하드웨어 뒤로 가기는 유지했다. 네이티브 포커스와 저장 완료 후 탐색이 직접 연결되어 있고, 메뉴 분리만으로도 읽기 경계가 명확해진다. 자동 저장의 소유자는 기존 `useEditor`다.
- 설정 전체 `busy`는 부모 화면에 남겼다. 서버 폼을 별도의 busy로 바꾸면 다른 설정 작업과 동시에 실행되는 동작이 달라진다. 기존 `BackupImport`와 `RecoveryKeyBackup`은 이미 독립된 작업 수명과 인증 처리가 있어 다시 나누거나 다른 오류 처리기와 합치지 않았다.
- 서버 키 등록과 평문 이력 검사, receipt·change 기록·영구 삭제 정리, 메모 push/pull은 NotesRepository에 남겼다. 키를 최초 등록할 수 있는지의 판단은 해당 계정의 기존 notes/changes/receipts 상태와 연결된다. 짧은 메서드를 별도 서비스로 감싸면 위임만 늘어난다.
- 인증·health·공통 오류 처리와 Fastify의 인증 scope 생성은 app.ts에 남겼다. 새 플러그인 scope나 범용 라우트 등록 프레임워크는 만들지 않았다.
- 암호화·무결성 검증·재시도 UUID·전송 순서와 네이티브 모듈 설정은 바꾸지 않았다. 의미가 다른 취소/오류 흐름을 공통 비동기 실행기로 통합하지 않았다.

## 검증과 한계

작업 전 기존 **129개**, 완료 시 **139개 / 25개 파일**이 통과했다. 추가한 10개 테스트는 가져오기 커밋 중 인증 세대 폐기와 대기 쓰기 진행, checkpoint 실패 시 원문/cursor 롤백, 내보내기 취소·공유 실패 시 캐시 정리, 늦은 미리보기·네이티브 data URI 오류의 비노출·큐 복구, 로그아웃 순서/실패, 휴지통 취소와 update→back 순서, 분리한 모든 라우트의 인증 scope를 검증한다.

소스 스냅샷과 AST를 비교해 LocalStore 공개 메서드 목록, 핵심 트랜잭션 본문, 마이그레이션 SQL 리터럴, 화면의 텍스트·레이아웃·접근성 속성 선언이 유지됐음을 확인했다. 이벤트 핸들러의 이동은 별도로 코드와 관련 회귀 테스트로 확인했다. 정적 비교는 실제 렌더링 검증이 아니다.

`pnpm check-types`, `pnpm lint`, `pnpm test`, `pnpm build`, Expo `install --check`, Android/iOS JS export가 통과했다. 전체 `format:check`는 기존 `AGENTS.md`, `apps/mobile/tsconfig.json` 경고 2건으로 실패하며 변경 파일은 통과했다. 빌드된 서버의 production smoke는 임시 DB·파일·계정만 사용해 HTTP 첨부 업로드/다운로드, 동기화, DB+blob 백업/검증/복원, 재시작, 세대 갱신 후 이력 차단을 확인했다.

네이티브 의존성/설정 변경이 없어 이번 리팩토링에서 네이티브 재빌드는 실행하지 않았다. Windows 환경에서 iOS 네이티브 빌드도 실행하지 않았다. Docker 명령이 없어 컨테이너/볼륨 검증은 못 했다. 실제 S3·NAS·iOS/Android 실기기에는 접속하지 않았다. 인증·SecureStore·사진 처리·미리보기 등의 단위 테스트는 모킹이며 네이티브 동작을 검증했다고 주장하지 않는다.

확인된 자동화 회귀는 없다. 다만 React 폼 상태의 소유자가 자식 컴포넌트/훅으로 이동했고 네이티브 서비스의 import 경계가 바뀌었으므로, 실제 기기의 인증 취소·앱 전환·자동 완성·사진 선택·공유 및 키보드/포커스·뒤로 가기는 여전히 확인해야 한다. DB 및 프로토콜 마이그레이션은 필요하지 않다. 기존 키 교체·첨부 GC·백업 한도 등의 기능 제한도 이번 작업에서 변경하지 않았다.
